## 🟡 Medium & 🟢 Low Priority Issues

### MED-01 · Error Re-wrapping Discards Original Taxonomy in `createBranch`

- **Cause:** `createBranch` wraps `db.Branch.insert()` in a `try/catch` block and throws `new SheetDB.IntegrityError('Failed to create branch.')` in the catch handler.
- **Scenario:** If `db.Branch.insert()` fails due to a schema validation error (e.g. a missing required field), it throws `ValidationError`. The catch block intercepts this and throws `IntegrityError` instead.
- **Impact:** Downstream API controllers receive a misleading exception type, obscuring the actual schema validation details.
- **Fix:** Either re-throw the original error directly, or check error type before wrapping:
  ```javascript
  try {
    return db.Branch.insert(payload);
  } catch (e) {
    if (e instanceof SheetDB.ValidationError || e instanceof SheetDB.ConflictError) throw e;
    throw new SheetDB.IntegrityError('Failed to create branch: ' + e.message);
  }
  ```

### MED-02 · Missing Mutation Tracking in `createBranch` and `createPromoCode`

- **Cause:** Neither method accepts a `context` parameter, and they do not invoke `_trackMutation()`.
- **Scenario:** When branches or promo codes are created, the active `mutationManifest` in the request context is not updated.
- **Impact:** Downstream clients and synchronize jobs are not notified of changes to Branch and PromoCode tables, leading to stale cache issues.
- **Fix:** Add `context` parameter to signatures and invoke mutation tracking.

### LOW-01 · Direct Date Comparisons Instead of `isDate()` in `validatePromoCode`
- **Location:** `validatePromoCode` date validation check.
- **Problem:** Checks expiry using `new Date(promo.valid_until) < new Date()` without verifying object type via `isDate()`.
- **Fix:** Utilize the realm-safe `isDate()` utility from SheetDB Utils before doing direct date math.
